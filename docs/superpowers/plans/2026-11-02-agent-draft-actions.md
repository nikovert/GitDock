# Agent draft actions implementation plan

Goal: PR Agent review produces editable local draft comments; individual or all publication remains explicit. Have an agent make all fixes starts a managed PR coding-agent session with a default review/fix/test/commit prompt. Include the generated app icon in the source and app bundles.

User intent: add Agent review to PRs; all agent findings are drafts in the PR viewer until the user publishes all or selected ones. A fixes button asks an agent to review all comments, apply fixes and commit. Existing main is already pushed at a5a3339; the generated icon files have not yet been committed.

Architecture: extend the existing advisory chat JSON exchange with an optional review task and structured findings, defaulting old callers to chat. Keep reviews read-only. Import validated anchors into the same inline-draft storage; unavailable anchors become separately publishable general draft comments. Extend ordinary local tmux worktree launching with a pinned-head prompt. Root implements app orchestration/UI/publication and icon integration; two independent implementers own review protocol and fix launch respectively.

Decisions made for unspecified details: fixes run in a new GitDock worktree, not a shared dirty checkout. The launch sheet shows provider and editable default prompt, includes published comments plus local drafts, and the agent is asked to assess comments rather than blindly comply. Commits stay local; no automatic push, review publication, force changes, or unrelated process termination. Terminal-session status is shown as started/running, never falsely as completed. No return of the retired background review worker.

Global constraints: preserve ordinary chat wire compatibility and local preferences; never invent anchors; preserve edits during publication and unrelated drafts; no automatic ambiguous-write retry; protect account, PR, head and base identity; existing CLI sign-ins and no added runtime dependency; macOS14 Swift6.

1. Review protocol (agent): add optional ReviewChatRequest.task and ReviewChatResponse.findings, ReviewAgentFinding(body,path?,line?,side?), strict bounded validation and read-only Python adapter review instructions. Tests first for structured findings, empty findings, invalid/missing review output, legacy JSON and CLI errors. Preserve existing advisory flags.
2. Fix launch (agent): add AgentFixRequest/default prompt builder, AgentSessionManager launchFixes with expected-head check and literal prompt transport to fresh managed worktree/tmux coding session. Preserve ordinary launches. Test stale head/repository checks, quoting, comments as data, no push instruction, provider args, and initial prompt delivery using controlled commands, never live coding sessions.
3. Draft/app integration (root): backward-compatible general draft comments/provenance and run receipt state; per-PR/cancellable Agent review, exact target guards, bounded context with discussion; safe shared inline/general draft cards; selected/general/batch publication with exact-version cleanup. Per-card/header actions, fix prompt sheet/provider selection/local session jump. Tests for review import, navigation/account/commit races, cancellation/failure/deduplication, general individual/batch posting and concurrent edits.
4. Delivery (root): integrate provided PNG/icns assets into app/package scripts, documentation/screenshots, core/app/Python suites and repository checks. Independent review, fix findings, merge/push verified source to main and build local validation artifact. Real provider calls and GitHub writes remain user-triggered from product controls, not performed during implementation verification.

Pre-flight interfaces: protocol agent owns core ReviewChat models/client and Python adapter only; fixes agent owns core AgentSession launch files/new fix models only; root owns app models/views/tests. Fix request contains pinned head/base, PR key/account/provider and comment context; root supplies snapshot data. Review findings optional coords are checked against exact complete snapshot lines by app, never trusted for attachment. Both individual and batch draft publishing use the existing review receipt service.
