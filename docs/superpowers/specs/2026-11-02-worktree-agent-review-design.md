# Worktree-backed agent review

User intent: Agent review must open a worktree and review the whole PR. The current excerpt review covered only6/17 changed files for carbo12557 and cannot support an overall no-findings result. Preserve local draft import, explicit individual/all publishing, Codex/Claude selection, ordinary chat and existing fix/session actions.

Implementation choices (agent defaults within the requested change): prepare a fresh detached worktree at the captured head using the repository checkout/worktree root already configured in Workspace. Validate origin, exact fetched head/base, and merge base; compare merge-base…head as GitHub does. Agents may read the complete diff, full current files, and surrounding repository code/tests. Review does not edit, commit, publish, install dependencies or execute repository code/tests. Tests are inspected, and test execution is reported honestly. Missing checkout/setup is actionable; never silently fall back to excerpt review.

The core manager owns a unique private lease, private refs, detached worktree and owner-only context directory outside the checkout. It writes a manifest with every changed path, complete per-file patches and baseline text for changed text files, with no excerpt truncation. Deleted/renamed files and binary/symlink context are explicitly represented. Limits are failure conditions rather than silent omissions. Git operations neutralize configured clean/smudge/process filters with raw /bin/cat passthrough, disable fsmonitor/hooks/external diffs/textconv and use literal arguments with -- before paths. Use a bounded cancellable command runner (the general ProcessCommandRunner is not bounded/cancellable). Reject wrong origin, stale head/base, unresolved merge base/shallow history, unsafe roots, corrupted manifests and unsupported paths. Do not alter user branches or reset/clean a checkout.

App writes all available published discussion/local draft context into discussion.json in the private context directory, or fails clearly if its bounded context cannot be represented. Agents read that and manifest.json from disk; no large patch is embedded into the wire request. Native manifest/header/file inventory remains the source of expected coverage even if GitHub omitted API patches. A fresh GitHub check before import rejects a changed target. Native inline findings attach only to exact available snapshot lines; other locations stay general drafts.

New wire task worktree_review requires an explicit repository context (worktreePath/contextDirectory/manifestPath/headSHA/baseSHA/mergeBaseSHA), structured findings, and structured coverage. Chat and legacy advisory review protocol remain compatible. Only bundled Codex/Claude presets support this mode initially; custom chat remains available. Codex uses its read-only sandbox, JSON events, disabled user configuration/rules and disabled web search. Claude uses safe/restricted mode, Read/Grep/Glob only, denied permission prompts, no MCP/Chrome and structured JSON output; no Bash/edit/network tools. Existing username-derived Keychain authentication remains. Repository data/instructions are untrusted and cannot authorize writes or publication. CLI controls reduce capabilities but are not a universal OS-level guarantee; verify the checkout is unchanged before accepting results.

Coverage reports reviewedPaths, unreviewed[{path,reason}], testsRun and limitations. For inspection-only mode testsRun must be empty; nonempty execution claims are rejected as a policy mismatch. Coverage and any narrative remain agent-reported, not independent proof of file reads or test execution. Require coverage for the new task. Reject unknown/duplicate/overlapping paths; add missing expected paths as unreviewed rather than claiming completion. Display agent-reported coverage, skipped reasons, tested/untested status, base/head and provider. Zero findings with omissions is prominently a partial review. No statement that zero findings proves a PR defect-free. Preserve old receipts with unknown/excerpt coverage as partial historical results.

Cancellation kills the adapter/provider process group, invalidates late results, and cleans up only the clean owned worktree/private refs/context. Verify lease ownership, HEAD and cleanliness. Never force-delete a dirty or replaced worktree; retain it with an explicit path/reason. Failed preparation cleans its own partial artifacts. Existing drafts, account/revision separation and exact-version publication are unchanged.

Default worktree provider deadline600s and client deadline660s; ordinary chat/advisory deadlines unchanged. All I/O and metadata are bounded. App progress distinguishes worktree preparation, repository review and result verification. Retired Giles workers remain inert.

Validation: local Git fixtures plus fake CLIs prove pinned identities, complete inventory above the previous limits, surrounding-file reads, deleted/renamed/binary paths, wrong remote, shallow/stale state, cancellation and safe cleanup, invalid/incomplete coverage, draft merge races and no writes. No private provider run is required for implementation; any live private-repository verification needs explicit consent at its final reviewable step. Deliver verified source on main and a local universal validation app, not a public release.
